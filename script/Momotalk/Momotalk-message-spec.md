# AI Compressed Character Stories Spec

## 1. 需求概述

在现有 Academy Messenger 角色/皮肤通讯稿的基础上，新建一个独立输出文件夹，生成适合 AI 推理和长期角色记忆的压缩版纯文本。

核心目标：

1. **逐句保留可见对话文本**，不因为压缩而删掉角色或老师的对白。
2. **删除技术性元数据和重复排版**，降低上下文长度。
3. **用简洁、稳定的结构标记表达剧情顺序、分支、汇合和羁绊剧情边界**。
4. **每个 CharacterId/皮肤独立成文件**，避免不同皮肤被合并。
5. **正文使用简体中文**，角色名使用“基础角色名（皮肤/形态）”。
6. **不生成额外的角色索引文件**；文件名本身提供必要的唯一性。

本规格定义输出方案；实现只修改 Academy Messenger 的压缩输出模式，不修改外部 `ba-data-global` 数据，也不改变现有完整 TXT 输出模式。

## 2. 已确认的用户决策

| 项目 | 决策 |
|---|---|
| 主要用途 | 单角色长期记忆 |
| 主要输入 | 现有羁绊剧情稿对应的数据/结构 |
| 文件粒度 | 每个皮肤一个文件，以 CharacterId 区分 |
| 语言 | 简体中文 |
| 对话 | 逐句完整保留 |
| 分支 | 使用结构化分支块 |
| 羁绊边界 | 转换为简洁叙事式边界，不在正文显示数据库 ID |
| 图片/资源 | 保留 `[图片]` 和资源路径 |
| 长度 | 不设硬上限，优先完整保留对白 |
| 皮肤文件关系 | 完全独立，每个文件自包含 |
| 推理重点 | 时间顺序、因果、性格关系、口吻和可继续对话全部保留 |
| 索引 | 不生成角色索引或剧情索引 |
| 文件格式 | 纯 TXT |
| 正文标识 | 只保留角色名和皮肤名；不显示 CharacterId、MessageGroupId、FavorScheduleId 等技术 ID |
| 分支汇合 | 保留选项文本，但只记录共同后续，不猜测每个选项对应哪条反馈 |
| 文件名 | 允许使用 CharacterId 后缀确保唯一 |
| 正文标题 | 每个文件一行极简标题 |
| 缺失文本 | 优先使用现有简体转换文本；MessageTW 缺失时按可用语言字段回退 |
| CharacterId=0 | 单独生成 `系统_0.txt` |
| 纯选项消息组 | 保留 |
| 普通通讯 | 全部保留，保持完整时间顺序 |

## 3. 当前代码和数据背景

### 3.1 现有转换入口

主要脚本：

```text
Momotalk/academy_messanger_to_txt.py
```

主要输入：

```text
AcademyMessangerExcelTable.json
```

角色/皮肤映射使用的外部数据：

```text
raw/ba-data-global/DB/CharacterExcelTable.json
raw/ba-data-global/DB/CostumeExcelTable.json
raw/ba-data-global/DB/LocalizeCharProfileExcelTable.json
raw/ba-data-global/DB/ScenarioCharacterNameExcelTable.json
```

### 3.2 现有完整角色剧情稿

```text
result/Momotalk/academy_messanger_character_stories/
result/Momotalk/academy_messanger_character_story_reports/
```

当前验证数据规模：

- 角色/系统记录：257 个 CharacterId
- 通讯记录：15,426 条
- 羁绊剧情触发记录：1,077 段
- 羁绊剧情稿：257 个 TXT
- 完整羁绊剧情稿约 1.94 MB

现有羁绊边界规则：

- 非零 `FavorScheduleId`：当前通讯之后进入羁绊剧情。
- 下一个 `MessageCondition=FavorRankUp`：上一段羁绊通讯区间结束。
- `Answer`：老师选项。
- `Feedback`：选项后的角色反应。
- `NextGroupId`：消息顺序/后续关系。
- `PreConditionFavorScheduleId`：羁绊返回后的相关前置关系。

这些字段是生成压缩稿时的内部输入逻辑，但不应直接输出到压缩正文。

### 3.3 皮肤名称要求

角色正文和文件名必须使用已解析的显示名，而不是单纯 PersonalName：

```text
10004 -> 阳奈
10086 -> 阳奈（礼服）
10072 -> 咲希（泳装）
```

皮肤判断可综合：

- `CharacterExcelTable.DevName`
- `CharacterExcelTable.ScenarioCharacter`
- `CostumeGroupId`
- `CostumeExcelTable` 的资源字段
- `LocalizeCharProfileExcelTable` 的本地化简介
- 已确认的明确角色/皮肤映射

不能用“变体+编号”伪造未知皮肤名称。没有充分证据时，保留基础角色名，并在实现阶段保留内部审计能力。

## 4. 输出目录和文件命名

新目录固定为：

```text
result/Momotalk/Momotalk_message/
```

每个 CharacterId 生成一个独立 TXT：

```text
<安全化显示名>_<CharacterId>.txt
```

示例：

```text
阳奈_10004.txt
阳奈（礼服）_10086.txt
咲希（泳装）_10072.txt
系统_0.txt
```

规则：

1. 文件名中的 CharacterId 只用于文件唯一性和人工定位。
2. 正文不显示 CharacterId 或其他数据库 ID。
3. 使用 Windows 安全文件名处理，保留中文括号和中文角色名。
4. 同名基础角色/不同皮肤不得覆盖彼此。
5. 重新生成时只清理上一次由该输出模式生成并记录过的文件，不删除目录中无法确认属于本模式的其他文件。
6. 不额外生成索引文件；如实现需要内部清单进行安全清理，该清单不属于面向 AI 的输出。

## 5. 正文总体格式

每个文件使用纯 TXT，尽量少用空行和重复标题。

推荐结构：

```text
阳奈（礼服）——Academy Messenger 通讯

=== 章节1 ===
阳奈（礼服）: 老师，有关之前说的约定……

<选择>
1. 老师: 嗯，这次放假要去买阳奈的礼服！
2. 老师: 我一直盼望能和阳奈去购物的这天！
</选择>

阳奈（礼服）: 呵呵……谢谢老师说得这么热情

【此处触发羁绊剧情1，正文见《<显示名>_羁绊剧情》】

=== 章节2 ===
阳奈（礼服）: 老师，请问明天有时间吗？
```

### 5.1 标题

每个文件只保留一行标题：

```text
<显示名>——Academy Messenger 通讯
```

标题不写 CharacterId、消息组 ID、数据库表名或转换时间。

### 5.2 说话格式

统一使用：

```text
角色名: 对话文本
老师: 对话文本
```

不使用多余的 `[MessageGroupId]`、`[MessageCondition]` 或数据库字段标签。

角色名必须使用当前皮肤解析结果，例如：

```text
阳奈: ……
阳奈（礼服）: ……
```

### 5.3 显式换行

一条消息中的显式换行仍属于同一条多行对白，不拆成多条独立消息。

推荐形式：

```text
阳奈（礼服）: 第一行
第二行
```

这样既保留原文换行，也避免每一行重复角色名。原文中的字面 `\\n`、`#n` 和 `<br>` 应转换为实际换行。

## 6. 逻辑压缩规则

### 6.1 普通通讯

普通通讯完整保留，按源数据的时间/消息顺序输出。

只删除：

- 重复的消息组标题
- 数据库字段元数据
- 无意义的重复空行
- 内部跳转 ID

普通对白直接归属于最近的章节，不重复添加“普通通讯”标题。保留必要的逻辑词：

```text
=== 章节N ===
【此处触发羁绊剧情N，正文见《<显示名>_羁绊剧情》】
```

`=== 章节N ===` 表示一次新的普通通讯主线开始；这些标签是面向 AI 的语义标记，不是原始数据库字段。

### 6.2 老师选项

纯选项消息组必须保留，因为选项是角色关系和后续剧情的重要输入。

格式：多个老师选项统一放入一个 `<选择>` 块，并按源数据顺序编号；只有一个选项时直接输出老师对白。

```text
老师: 唯一选项

<选择>
1. 老师: 选项一

2. 老师: 选项二
</选择>
```

如果原始数据明确提供每个选项的独立反馈，应将反馈直接放在对应选项下，并统一放入同一个 `<选择>` 块：

```text
<选择>
1. 老师: 选项一
阳奈: 选项一的反馈

2. 老师: 选项二
阳奈: 选项二的反馈
</选择>
```

但是，如果原始数据只提供多个选项汇合到同一个后续消息组，不能猜测逐项反馈归属。使用：

```text
<选择>
1. 老师: 选项一

2. 老师: 选项二
</选择>

阳奈: 共同反馈内容
```

不能输出未经数据支持的“选项一导致某句、选项二导致某句”。

### 6.3 角色反馈

有明确选项来源时，直接将反馈接在 `<选择>` 块之后，不添加额外标题。

没有明确选项来源时，也直接按源顺序输出反馈，不添加额外标题。

如果多个选项汇合，直接按源顺序输出共同反馈，不重复复制同一段反馈。

### 6.4 章节与羁绊剧情边界

正文不显示 `FavorScheduleId`、`FavorRankUp` 或消息组 ID，使用两种简洁的语义标签：

```text
=== 章节1 ===
……本章节普通通讯……

【此处触发羁绊剧情1，正文见《<显示名>_羁绊剧情》】
阳奈: 羁绊剧情结束后接续的通讯……

=== 章节2 ===
……下一段普通通讯……
```

边界解释：

1. 第一个通讯组前输出 `=== 章节1 ===`。
2. 每个 `FavorRankUp` 消息组表示新的普通通讯章节开始；在该组对白前输出下一个 `=== 章节N ===`。
3. 非零 `FavorScheduleId` 所在的通讯属于进入羁绊剧情前的最后一段通讯。
4. 该通讯完整输出后，紧接着输出 `【此处触发羁绊剧情N，正文见《<显示名>_羁绊剧情》】`。
5. `PreConditionFavorScheduleId` 只用于在触发记录缺失时恢复同样的羁绊标记，不输出数据库 ID。
6. 羁绊后的通讯继续按源数据顺序输出，直到下一个 `=== 章节N ===`。
7. 不输出“开始/结束，恢复普通通讯”等冗余边界文字；章节标记本身表示从羁绊后恢复普通通讯。

### 6.5 图片和资源

图片记录不能完全删除，因为它可能是通讯事件的一部分。使用：

```text
[图片: <完整资源路径>]
```

不额外输出 MessageType、MessageGroupId 等字段。

### 6.6 缺失文本回退

优先级：

1. `MessageTW`，转换为简体中文。
2. `MessageJP`，转换/保留为可用简体内容，并可在同一行追加简短语言标记。
3. `MessageEN`。
4. 其他已有可用语言字段。
5. 所有语言均为空时，输出：

```text
[缺少对话文本]
```

不根据上下文自动编写貌似原文的对白。语言回退应尽可能简洁，例如：

```text
阳奈: <回退后的文本>
```

如实现确实需要记录回退来源，使用 `[语言回退]` 这种简短标签，不输出完整字段名和数据库元数据。

## 7. AI 友好性要求

### 7.1 必须保留

- 所有角色对白原文内容
- 所有老师对白和老师选项
- 对话出现顺序
- 分支开始、分支反馈和共同汇合关系
- 羁绊剧情进入位置和章节恢复边界
- 角色/皮肤显示名
- 图片事件及资源路径
- 纯选项消息组
- 普通通讯，不因未紧邻羁绊剧情而删除

### 7.2 应删除或压缩

- `MessageGroupId`
- `NextGroupId`
- `FavorScheduleId`
- `PreConditionFavorScheduleId`
- `MessageCondition` 的数据库原文值
- `FeedbackTimeMillisec`
- 重复的“=== 消息组 ===”标题
- 重复的角色/文件元数据
- 空记录的详细字段快照
- 不能帮助 AI 推理的技术路径（图片路径除外）

### 7.3 防止错误推理

- 不猜测多个选项与反馈的逐项对应关系。
- 不把数据库 ID 当成剧情编号展示。
- 不把未确认的皮肤命名成“变体100xx”。
- 不把不同 CharacterId 的皮肤合并成一个对话身份。
- 不把 ScenarioScript 中无法可靠关联的其他剧情正文插入 Academy Messenger。
- 不因压缩而改变原始消息顺序。

## 8. 代表性示例

### 8.1 阳奈基础形态与礼服形态

基础文件：

```text
阳奈_10004.txt
```

正文对白前缀：

```text
阳奈: 老师。这次休息日的深夜，有空吗？
```

礼服文件：

```text
阳奈（礼服）_10086.txt
```

正文对白前缀：

```text
阳奈（礼服）: 老师，请问明天有时间吗？
```

两个文件必须完全独立，不能把礼服形态对白合并到阳奈基础形态文件中。

### 8.2 选项汇合

```text
<选择>
1. 老师: 选项一

2. 老师: 选项二
</选择>

阳奈（礼服）: 呵呵……谢谢老师说得这么热情
```

不得写成：

```text
选项一 -> 这句反馈
选项二 -> 另一句反馈
```

除非原始数据明确提供这种对应关系。

### 8.3 章节与羁绊边界

```text
=== 章节1 ===
阳奈: 老师。虽然有点突然，但我想和你谈谈
……
阳奈: 这么晚真是抱歉，那么地点是……

【此处触发羁绊剧情1，正文见《<显示名>_羁绊剧情》】
阳奈: 是不是因为我的关系，睡眠时间变少了？
阳奈: 晚安，老师

=== 章节2 ===
阳奈: 老师。这次休息日的深夜，有空吗？
```

## 9. 非目标

本次规格不要求：

1. 把独立 ScenarioScript 羁绊剧情正文自动拼入 Messenger。
2. 生成全角色检索索引、向量数据库或 JSONL。
3. 对普通通讯进行摘要或删减。
4. 自动推断未被源数据支持的选项反馈关系。
5. 修改仓库内 `raw/ba-data-global` 数据。
6. 修改现有完整 TXT 输出目录的格式。
7. 使用模型二次改写或润色对白。

## 10. 验收标准

实现后至少应满足：

### 文件和数量

- 创建 `result/Momotalk/Momotalk_message/`。
- 为当前 257 个 CharacterId 生成 257 个 TXT，包括 `系统_0.txt`。
- 文件名按显示名和 CharacterId 唯一，不发生覆盖。
- 不生成面向用户的索引文件。

### 角色/皮肤

- `10004` 显示为 `阳奈`。
- `10086` 显示为 `阳奈（礼服）`。
- `10072` 显示为 `咲希（泳装）`。
- 基础形态和皮肤形态的正文说话人名称正确区分。
- 不出现 `角色(100xx)` 这类已知角色兜底名。
- 不出现 `变体100xx` 这类伪皮肤名。

### 内容和逻辑

- 所有源通讯文本均可在压缩文件中找到，逐句内容不丢失。
- 所有老师选项均保留。
- 纯选项消息组不被过滤。
- 选项汇合场景只输出共同后续，不做未经证实的逐项配对。
- 羁绊剧情进入位置和章节恢复边界保留，但正文不出现数据库 ID。
- 普通通讯完整保留并保持顺序。
- 图片保留 `[图片: 路径]`。
- 缺失 MessageTW 时按既定语言字段回退，所有字段为空时使用 `[缺少对话文本]`。
- 不出现字面量 `\\n` 代替实际换行。

### AI 输入质量

- 正文不包含重复消息组标题和冗余数据库元数据。
- 角色名、老师、选项、反馈和共同后续具有稳定格式。
- 同一文件可以脱离其他皮肤文件独立理解。
- 文件不强制硬性 Token 上限，但应明显短于对应完整角色剧情稿。

## 11. 后续实现建议

实现时可在 `Momotalk/academy_messanger_to_txt.py` 中新增独立转换模式，例如：

```bash
python script/Momotalk/academy_messanger_to_txt.py \
  --input AcademyMessangerExcelTable.json \
  --Momotalk_message
```

建议实现为独立函数和独立输出目录，不改变已有：

```text
--by-character
--character-stories
--stories
```

现有角色/皮肤解析器、羁绊边界识别、选项/反馈分类和文本清理函数应尽可能复用。实现完成后再针对 10004、10072、10086 以及存在分支汇合的角色进行回归验证。
